Shared DIGIT token preservation for logout scope=others
Source tested: a22b65f07 (base: identity/completion-base69f9af553)
Task: task_36a3f61c33814e998119686124e65d18

Observed real gate symptom: 8c-gate-report.md reported that logout-others
kept the current BFF session but invalidated its shared DIGIT access token.
The report did not record the Redis inventory/holder topology.

Reproduction boundary:
- Accurate same-account/same-token holders already pass on base69f9af553.
- A plausible variant fails there: an additional tenant-alias inventory entry
  for the same UUID/token is held only by an ended session. Revoking through
  that entry invalidates the token still held by the current session.
- This proves the variant, NOT the cause of the 8c observation. Owner approved
  scoped protection for this variant on the identity-gate-fixes bridge thread.
- Before code change, the two new regression cases yielded 1 pass / 1 fail.
  Failed case: logout others keeps current shared token (duplicate inventory).
  No live token/cookie values are included in this evidence.

Implemented:
- Snapshot current-session-held accounts and token values under the person
  lease before ending the other BFF/Keycloak sessions.
- Preserve current holder/inventory; skip external logout and retry enqueue
  for any protected token, including duplicate inventory aliases.
- Forget an unheld duplicate alias record after ending its other sessions.
- Other-only tokens still revoke. Current/all use their existing behavior.
- Frozen contract section8 documents that other consumers of a retained shared
  token can continue until expiry/account-wide revocation. Logout section3.3.2
  and core-internals API comment match this limitation.
